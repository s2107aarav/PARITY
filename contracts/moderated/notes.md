# Moderated ticket challenge

V1 POST /tickets takes {title,body}, strings length1..200, Idempotency-Key1..120. Atomic 201 {id:positive integer,title,body,status:"open"}. Same full body/key returns same ticket; changed body409 {error:"KEY_REUSED"}. GET /tickets/{integer} returns ticket or404 {error:"NOT_FOUND"}. Invalid input422 {error:"INVALID"}.

Successor: POST /issues {summary}, Idempotency-Key creates UUID {ref,summary,state:"draft",comments:[]}. POST /issues/{ref}/comments {text} sets one initial comment idempotently. POST /issues/{ref}/approve (no body) requires comment and returns {receipt,issue_ref}; receipt is durable and repeating approve returns the same receipt. POST /issues/{ref}/publish REQUIRES JSON {receipt: exact approval receipt} and returns issue with state open. GET /issues/{ref} returns issue. Draft key conflict409 KEY_CONFLICT; invalid schema422 INVALID_INPUT; missing404 MISSING_RESOURCE; errors {problem:{kind:CODE}}.

Unlike the earlier ticket fixture, publication cannot succeed without a returned approval capability. Preserve the full legacy fingerprint (including description), issue ref, receipt and progress in durable state. Both approve and publish can return503 AFTER commit: return503 {error:"PENDING"}, then reconcile on same-key retry, including after adapter restart. Never manufacture an approval receipt or return success for a draft. No background recovery. ctx.lock/get/put/id_for/upstream_id/call are the standard runtime ABI. Invalid legacy inputs must be rejected before effects. A single host and no external writers are assumed. Only create/retrieve is supported.
